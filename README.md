# PIGDEX 081

> **宅邸友情力荐：** [fount](https://github.com/steve02081504/fount) —— 让想象获得声音，也获得自由生长的可能。

> **Vesperion Porcine Archive · 维斯珀里昂猪类与异常现象图鉴**

一座持续生长的私人自然史宅邸，用于收录 Specimen №081 在日常生活、知识兔子洞与互联网深处留下的不同形态。现馆藏 **59 种猪咪形态**与一套完整的 **78 张《猪猪塔罗牌》**，并设有猪种鉴定所、宅邸档案室、猪事馆、猪猪教堂、猪语翻译器、PIGLIZA 会客室、抽牌桌及制度文件室。

**在线访问：** [xiaoqiush81.github.io/vesperion-porcine-archive](https://xiaoqiush81.github.io/vesperion-porcine-archive/)

**最新入馆：** PIGLIZA · 猪莉莎二代内核启用；将中文分析、语义帧、对话策略、受约束生成和显著性记忆分层组合，以约 300 行核心流程配合独立数据获得千级响应路径，全程本地运行且不连接语言模型。

PIGLIZA 继承 Joseph Weizenbaum 于 1960 年代提出的 ELIZA 会话思想；工程调研参考了 [Steve02081504/ELIZA](https://github.com/steve02081504/ELIZA) 的职责分层，但引擎、中文规则、回答模板与界面均为独立实现。

## 设计与体验

- **双色主题：** 象牙白与夜色主题均由语义化 CSS 变量驱动，组件不绑定固定颜色。
- **响应式宅邸：** 针对 iOS Safari、桌面浏览器和旧设备分别处理固定顶栏、安全区、触控与排版。
- **一致的内容层级：** 图鉴详情、猪事馆目录与卷宗均使用独立响应式布局，移动端纵向阅读，桌面端保留舒展留白。
- **诗体专属排版：** 猪诗卷宗保留原作分行，公开外馆与私藏内馆共享同一套可展开阅读体验。
- **渐进式图像加载：** 塔罗陈列优先加载轻量缩略图，打开详情时再载入高清牌面；关键资源会提前预热。
- **模块按需进入：** 图鉴、鉴定、塔罗、档案室、猪事馆与猪猪教堂仅在访问对应房间时加载，避免首屏承担整座馆舍的资源成本。
- **可分享房间路由：** 各馆舍使用 `?room=...` 地址，可直接打开并兼容早期 `#...` 链接。
- **完整浏览器图标：** 提供 ICO、16/32/48px 标签页图标、180px Apple Touch Icon 及 192/512px Web App 图标。
- **本地优先：** 收藏、鉴定记录、占卜记录、猪猪教教籍、主题及声景偏好保存在当前浏览器，不依赖账户或远端数据库。
- **无构建运行：** 使用原生 HTML、CSS 与 ES Modules，可直接由静态服务器及 GitHub Pages 托管。

## 本地运行

本项目使用 ES Modules，需通过 HTTP 服务器访问：

```bash
python3 -m http.server 8080
```

然后打开 [http://localhost:8080](http://localhost:8080)。无需安装依赖或执行构建。

## 扩充馆藏

### 添加猪咪形态

1. 按现有结构向 `data/specimens.json` 追加记录。
2. 将对应 WebP 卡面放入 `assets/cards/`。
3. 保持档案 ID、卡面路径与分类字段唯一且一致。

页面会自动生成卡片、分类筛选、搜索索引与详情档案。若新形态需要参与鉴定或塔罗联动，再分别编辑 `assets/js/identity-data.js` 或 `assets/js/record-links.js`。

### 扩充鉴定题库

题目集中维护在 `assets/js/identity-data.js`。题库按观察维度分组，鉴定引擎会从不同维度随机抽题，并尽量避开上一轮题目；扩题不需要修改界面或匹配流程。

作答先选择、再进入下一项；返回不会删除后续选择。未完成题组与选项以题目 ID 保存在本地，刷新或恢复档案后继续；过期题目不会带入新题库。签发结果只记入一次近期档案，档案室每次进入时刷新统计。

便携档案采用 v3 格式，覆盖收藏、鉴定记录与进度、占卜、诸科与课外综合作答、教籍、猪谕、猪莉莎谈话、主题与声景。v1/v2 旧档仍可导入，缺失项目保持当前值。文件先完整校验，再由用户确认覆盖范围；写入失败会尝试回滚，并明确报告回滚是否成功。

### 调整塔罗系统

- 牌面资料与牌阵：`assets/js/tarot-data.js`
- 洗牌、正逆位与补牌逻辑：`assets/js/tarot-engine.js`
- 占卜记录：`assets/js/tarot-storage.js`
- 塔罗交互界面：`assets/js/tarot.js`

### 整理猪事馆

公开卷宗集中维护在 `data/chronicles.json`，界面、分类切换、分卷和展开交互由 `assets/js/chronicles.js` 负责。新增记录只需归入对应馆藏与猪史分卷，不需要复制页面结构。

「诸科笺注」是一套独立馆舍与跨学科题库，只在内外馆猪诗卷末保留低调馆印，不进入主导航。题目、原文、学科与参考答案不会以明文进入当前仓库，而是集中封装在 `data/scholia.enc.json`：访问者提交本地凭证后，由浏览器使用 PBKDF2（SHA-256）派生 AES-256-GCM 密钥并在内存中解密，凭证与解密后的题库均不会写入 localStorage 或上传。解锁后仍由同一套小室模板负责九科切换、作答与答案对照。

维护题库时，在仓库外保留明文 JSON，并使用 `tools/encrypt-scholia.mjs` 重新生成密卷；密码通过环境变量 `SCHOLIA_PASSWORD` 传入，不得写入源码、README、提交信息或数据文件。题库仍只在真正开启时延迟加载，不增加首页负担。\n\n如需批量翻新题目，先在仓库外维护 `vesperion-scholia-maintenance-patch` 格式补丁，再运行 `node tools/apply-scholia-patch.mjs <plain.json> <patch.json> [output.json]`。脚本会校验材料/题目 ID、删除项、替换项和已审保留项，避免靠手工复制修改密卷；补丁文件同样不得提交到公开仓库。

「课外综合」从诸科目录第十格进入，但与加密的猪诗题库解耦。它复用九科小室与作答界面，内容集中维护在 `data/extracurricular.json`；材料可来自科技、互联网、生活观察等课外主题，只给真正相关的学科出题，其余小室允许为空。

公开记录应当经过无痕改写后自然成篇，不得提及删去、隐去、另存内馆或涉及现实身份等编辑过程，也不得用标题、括注或卷末说明暗示原文尚有敏感内容。需要保护的信息直接不写，不留下可供反推的缺口。

### 替换图标或声景资源

浏览器图标默认使用 `assets/icons/` 中的同源文件，以保证 Safari、Chrome、Edge 与 Firefox 的稳定读取。需要临时使用图床或自定义音乐、音效时，可在 `assets/js/site-assets.js` 中填写 HTTPS 地址；留空即沿用本地图标及内置声景。

## 数据与隐私

本站没有账户系统，也不会把鉴定答案、收藏、塔罗问题、诸科与课外综合作答、笔记或猪莉莎谈话上传至宅邸服务器。业务数据默认仅存在当前浏览器的 `localStorage` 中；清理网站数据、更换浏览器、无痕会话结束或设备存储回收都可能使记录消失。

公开页面由 GitHub Pages 托管，字体由 Google Fonts 提供；相关基础设施仍可能依其自身政策处理完成网络请求所必需的技术信息。完整说明以站内“条款与政策”为准。

## 兼容性

- 优先支持当前版本的 Safari、Chrome、Edge 与 Firefox。
- 标签页、地址栏、Safari 历史记录、Apple Touch Icon 与 Web App Manifest 使用对应尺寸资源，不依赖运行时缩放同一张大图。
- iOS Safari 的音频必须由用户手势启动；切换后台后会按页面生命周期恢复或暂停。
- `localStorage`、Web Audio 或私密浏览限制不可用时，核心浏览功能仍可使用，相关偏好可能无法持久保存。
- 旧设备会先显示轻量资源并延后加载非当前房间模块，以减少首屏空白与解码压力。

## 部署

仓库使用 GitHub Pages。推送到 `main` 分支后，GitHub Actions 会自动发布静态站点；无需服务器、数据库或运行时密钥。

## 档案守则

- 核心编号始终为 `081`；其他字母与后缀表示同一标本的不同形态。
- 只记录已经观察到的猪咪现象，不得捏造不存在的罪名。
- 捕获率固定为 `0.00%`，但收藏不受此限制。
- 猪咪尾巴、耳朵、鼻头与蓬松程度均受宅邸制度文件保护。
